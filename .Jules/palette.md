## 2026-06-14 - Enhanced Login Dialog Accessibility and Feedback
**Learning:** Adding a password visibility toggle greatly improves UX, especially when creating or verifying secure passwords. Ensuring the toggle uses an `aria-label` allows screen readers to provide context for the action, while updating the label based on the state ("Show password" / "Hide password") offers dynamic feedback. Using a `Loader2` spinner with `"Please wait..."` keeps the user informed and prevents redundant submissions during async operations.
**Action:** Always include an accessible (aria-labeled) visibility toggle in password inputs and pair disabled loading buttons with a clear visual indicator (like a spinner) and informative text.

## 2026-06-14 - Semantic Wrappers and ARIA Labels for Truncated Content
**Learning:** When rendering dynamic lists of items like tasks in Kanban, Gantt, Calendar, or List views, where items are interactive but visually truncated using `text-overflow: ellipsis` or similar constraints, standard `div` elements with `onClick` handlers fail to provide sufficient context or affordance for keyboard and screen reader users. Screen readers only announce what is visible or what the implicit role is, meaning truncated content without accessible names remains hidden.
**Action:** Always use semantic interactive elements (like `<button>`) or `role="button"` for clickable wrappers. Ensure they have explicit `aria-label`s providing the full context (e.g., `aria-label={"Task: " + task.title}`) and include `focus-visible` styles (`focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-offset-2`) so keyboard focus is clear. For table rows, remember to add `role="button"`, `tabIndex={0}`, and `onKeyDown` handlers for Space/Enter activation.

## 2026-06-14 - Refining Interactive Wrappers and Table Semantics
**Learning:** Adding an `aria-label` to a container with rich inner content (like a complex Kanban card) overrides all the inner content, preventing screen readers from accessing dates, tags, and assignees. Furthermore, adding `role="button"` to a `<tr>` element breaks table navigation for screen reader users by removing its row semantics.
**Action:** When making complex cards accessible, do not use `aria-label` on the wrapper unless it's genuinely the only piece of context needed (e.g., an icon-only button). For rich cards, let the native text content provide the accessible name, or use `aria-labelledby` to point to specific IDs within the card. For tables, avoid adding `role="button"` to `<tr>`. Instead, keep the row clickable but rely on native row semantics or embed standard buttons inside the cells if needed.
