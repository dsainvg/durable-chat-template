## 2026-05-18 - Batch Database Updates and Coalesce Polling Endpoints
**Learning:** Polling loops in the frontend (e.g., active user tracking) shouldn't separate "update" requests (heartbeats) and "fetch" requests (status retrieval) into distinct API calls. Separating them literally doubles the request volume hitting the server unnecessarily. Also, on the backend, sequential database updates and reads in Cloudflare D1 can be combined into a single transaction using `db.batch()` to prevent multiple unnecessary database roundtrips.
**Action:** Always combine synchronous write+read operations in high-frequency polling scenarios. Ensure that write operations return the read data context if the client will immediately need it, and leverage `db.batch()` when making multiple database mutations back-to-back.
